No source-library code was copied, executed, installed or bundled. Expected angles and
cusps are published assertions, not values generated by AstroEye. The reference uses
related classical geometry, so agreement is not proof that all shared assumptions are
correct. Its numeric degree values are used, not its sign labels or sidereal zodiac.

## Conventions and tolerances

The source uses mean sidereal time and fixed obliquity 23.4367 degrees. AstroEye uses
apparent sidereal time and date-dependent true obliquity. Both comparisons are tropical.
The fixture uses UTC instants explicitly asserted by the source's Origin tests rather
than inferring offsets from city names. Source month 6 means July, not June.

Two separate checks prevent hiding these differences:

1. **Matched orientation:** pass the published sidereal value and fixed obliquity into
   AstroEye's pure angle seam. The preselected tolerance is 0.36 arcseconds, twice the
   source's four-decimal-degree rounding half-step.
2. **Date/location:** run the unmodified production date-based angles and houses. A
   preselected 60-arcsecond threshold screens large discrepancies for these two
   non-polar 2019 examples. This allows convention differences; it is not a derived
   accuracy bound. Whole Sign cusps must match exactly rather than approximately.

Do not widen either threshold after seeing a failure. Investigate inputs, conventions
and algorithms, then explicitly review any proposed change to the reference contract.

## Run and maintain

`node scripts/astroeye-angle-references.mjs` prints both types of error and exits nonzero
on comparison failure. It only reads the stored JSON fixture; it has no network mode.

`node --test src/modules/astroeye/calculation/publishedAngles.test.mjs`

Tests cover published agreement, unchanged fixture input, missing-cusp honesty, shifted
UTC, reversed longitude, wrong antipode, shifted cusps, malformed data and refused
tolerance/provenance changes. Together with `angleGeometry.test.mjs`, 10 tests passed
on 2026-09-13. Reference refreshes require manual source review at a pinned commit;
never regenerate expected values from production calculations.

The complete platform suite passed with 222 tests. This checkpoint adds only fixtures,
offline verification code and documentation, so no production build or browser run was
repeated. The user's open preview and saved records were not accessed.
