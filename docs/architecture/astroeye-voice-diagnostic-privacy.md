# Voice diagnostic privacy and size policy

October 5, 2026, checkpoint 132, based on `33597f0`. Partial L2 security review,
not live-voice acceptance or authorization for public deployment.

## Finding and changed behavior

The old controller automatically posted diagnostic payloads, and the server
appended arbitrary JSON to `.gev-logs/realtime-conversations.jsonl`. Client-side
secret-pattern redaction did not exclude transcripts/tool content, was bypassable
by direct requests, and did not bound the total file size. No existing logs were
opened to investigate this finding.

Diagnostic transmission and server writes are now **off by default**. Only the
exact server environment setting `GEV_VOICE_DIAGNOSTICS=1` enables recording.
The client gets a boolean through Vite's explicit define; rebuild/restart is
required when changing the setting. The existing environment and API key were
not edited, and diagnostics were not enabled for the user.

When explicitly enabled for local troubleshooting:

- The client sends only a known event name and a fixed status code. It does not
  serialize diagnostic payloads, session IDs, transcripts, tool arguments/results,
  screenshots, coordinates or error messages.
- The server independently applies that same finite allowlist. It ignores extra
  fields from older/full clients, rejects unknown event names, and substitutes
  `unknown` for unrecognized statuses. The timestamp is generated by the server.
- Requests have a 4 KiB read limit; disabled requests do not read bodies or touch
  storage. Responses use no-store and fixed errors without filesystem details.
- Only the new `.gev-logs/voice-diagnostics-v1.jsonl` file is used. It stops growing
  at **256 KiB** and reports a full-log failure rather than truncating/rotating data.
  The size check and append are serialized synchronously within one server process.
  The sink rechecks the allowlist and rejects symlink directory/file targets.

This is a deliberately limited troubleshooting log, not a conversation replay.
It loses rich payload diagnostics in exchange for excluding private content.

## Retention and limitations

There is **no automatic time-based expiry**. Metadata remains on disk until the
owner removes it. Disabling logging stops new writes; it does not remove history.
Old `realtime-conversations.jsonl` files may contain private information and are
neither read, modified, migrated nor deleted by this change. Their review/deletion
requires a separate user decision. No material user data was deleted.

The cap is per file and single-process, not a disk quota, cross-process lock,
request-rate limit, or defense against a local attacker racing filesystem paths.
Do not enable this endpoint publicly without access/origin/retention policy review.
The flag is configuration, not per-browser user consent or authentication.

This change covers diagnostic POSTs and their server file only. Existing browser
recent-error storage/console messages, live provider transmissions and user-exported
diagnostic reports are separate surfaces; no blanket no-recording claim is made.
The local error store and remaining upstream resource/access controls still need
review, as do provider/data/asset rights. Live microphone/provider testing continues
to require separate explicit approval.
